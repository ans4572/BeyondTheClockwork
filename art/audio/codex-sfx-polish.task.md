# Codex 작업: 효과음 다듬기 — 톡톡 튀는 느낌 줄이기 (2026-11-09)

저장소 루트(`Beyond the Clockwork`) 기준 경로입니다. **효과음 코드만** 고칩니다. 게임 규칙·데이터(`src/engine/`, `src/data/`), 그림, 배경음악, 테스트 기대값은 건드리지 않습니다. 커밋과 푸시는 하지 않습니다.

## 배경

이 게임의 효과음은 녹음 파일 대신 대부분 Web Audio로 코드 합성합니다. 소리마다 후보 레시피가 있고, `src/audio/sfx.js`의 `SFX` 표가 게임에서 쓰는 후보와 음량을 고릅니다.

| 파일 | 내용 |
| --- | --- |
| `src/audio/coded.js` | 플레이어(렌치·회피·피격 등), 1장 몹, 1장 보스, 메뉴, 얼음 속성 |
| `src/audio/elements.js` | 불·전기·바람 속성, 1장 융합, 마을 종, 포털, 실패 나팔 |
| `src/audio/water-sound.js` | 물·소리 속성과 그 융합(2026-11-09 추가) |
| `src/audio/boss2-sound.js` | 2장 보스 아이리스·프레스 패턴(2026-11-09 추가, 도구 함수는 `water-sound.js`에서 가져옴) |
| `src/audio/sfx.js` | `SFX` 표(이름 → 후보·음량), `SoundBank.play`/`stop` |
| `sounds.html` | 게임에 들어 있는 효과음 전체를 번호(A1, H3 …)로 들어 보는 페이지 |

**문제:** 사용자가 "속성, 몹, 보스 효과음이 너무 톡톡 튄다"고 했습니다. 귀에 거슬리는 원인으로 보이는 것:

1. **어택이 너무 짧음:** 노이즈·톤을 0.001~0.002초 만에 최대 음량으로 올림(`attack: 0.001`, `decay(… 0.001 …)`, `crackle`의 1ms 클릭, `band(… dur: 0.02 …)`). 클릭처럼 들림.
2. **고음이 날카로움:** 2.5~7kHz 하이패스·밴드패스 노이즈(`snap`, `crackle`, `band(type: 'highpass', freq: 3000+)`), 사각파(`type: 'square'`)·톱니파가 필터 없이 나감.
3. **공간감이 없음:** 모두 완전히 마른 소리라 짧은 소리가 '톡' 하고 끊김.
4. **똑같이 반복됨:** 같은 소리가 연달아 날 때(렌치 연타, 도장, 박자 압착, 물보라) 높이·음색이 매번 같아 기계적으로 들림.
5. **소리 크기 차이:** 일부 소리는 짧은 피크만 커서 같은 음량에서도 튀어 들림.

## 목표

같은 소리의 **성격과 타이밍은 그대로 두고**(무엇인지 알아들을 수 있게), 다음처럼 부드럽게 만듭니다.

- 모든 시작(어택)은 **최소 4~8ms**. 타격감이 필요한 렌치·강타·압착은 4ms, 나머지는 6~10ms.
- 클릭·딱 소리 층은 **6kHz 위를 깎거나**(lowpass 또는 highshelf −6dB) 음량을 줄여 몸통 소리 밑에 깔리게.
- 사각파·톱니파는 lowpass(대략 2~3kHz)를 거치거나 삼각파로 바꿈. 단 1장 칩튠 느낌이 필요한 메뉴 소리(카드, 고르기 등)는 그대로.
- **짧은 공간 울림 하나를 공용으로**: `SoundBank`(sfx.js)에서 코드 합성 소리에만 작은 리버브 센드(코드로 만든 0.25~0.4초 감쇠 임펄스의 `ConvolverNode`, 젖은 소리 8~15%)를 붙임. 소리마다 다르게 할 필요는 없음. 메뉴 소리는 빼도 됨.
- **가벼운 변주:** 자주 반복되는 소리(렌치 1·2타 적중, 도장, 박자 압착, 피스톤, 물보라, 물막 울림, 거울판 돌리기, 몹 공격)는 재생할 때마다 높이 ±3% 안에서 조금씩 달라지게(`play`에 선택 옵션으로).
- **마스터 정리:** 코드 합성 소리 출력 끝에 부드러운 `DynamicsCompressorNode`(threshold −18dB, ratio 3~4, knee 10)와 피크 제한을 둬서 짧은 피크가 튀지 않게. 녹음 파일 소리(구매·조율·거부·장착)에는 걸지 않음.

## 범위 (모두 다듬음)

- **속성 기술과 융합:** `sounds.html`의 B(속성 기술), C(융합), H(물·소리 속성 17개)
- **몹:** D(적) — 1장 몹 공격
- **보스:** E(1장 보스·마을), I(2장 보스 24개)
- **J(2장 적 9개, `src/audio/mob2-sound.js`)**는 2026-11-09에 처음부터 이 기준(어택 5ms 이상, 5kHz 아래, 높이 변주)으로 만들었으므로 레시피는 두고 공용 리버브·컴프레서만 걸리면 됩니다.
- **플레이어 기본(렌치 적중·강타·피격)**은 손대지 않아도 되지만, 위 공용 리버브·컴프레서가 걸려도 괜찮은지 들어 보고 어색하면 그 소리만 빼기

## 지켜야 할 것

1. **이름과 연결은 그대로:** `SFX`의 이름, 고른 후보 번호, 게임이 소리를 내는 순간(엔진의 `sense`)은 바꾸지 않습니다. 레시피 안쪽과 `SoundBank`만 고칩니다. 새 후보를 추가하는 대신 **고른 후보 자체를 다듬습니다.**
2. **녹음 파일·외부 라이브러리 금지:** 지금처럼 Web Audio 노드만 씁니다. 새 패키지를 설치하지 않습니다.
3. **소리 크기 유지:** 다듬은 뒤 각 소리의 "가장 시끄러운 50ms 구간의 RMS"가 다듬기 전과 ±1.5dB 안이어야 합니다(필요하면 `SFX` 음량을 조정).
4. **가볍게:** 소리 하나가 만드는 오디오 노드는 대략 40개 이하. 리버브 임펄스는 한 번만 만들어 재사용합니다.
5. **멈춤 기능 유지:** `SoundBank.stop`(고압 분사를 놓으면 소리가 멈추는 기능)이 리버브를 거친 뒤에도 0.1초 안에 조용해져야 합니다.
6. **테스트:** `npm test`가 전부 통과해야 합니다(지금 402개). `test/music.test.js` 등 기존 테스트를 고치지 않습니다.
7. **모바일:** iOS Safari에서도 동작하는 API만(OfflineAudioContext는 길이를 정수 샘플로, `AudioParam` 값은 유한한 숫자로).

## 확인 방법

1. 개발 서버(`npm run dev`, 포트는 실행 중인 것 사용)에서 `sounds.html`을 열어 B·C·D·E·H·I 묶음을 하나씩 들어 봅니다.
2. 측정 스크립트를 임시 폴더에 만들어(저장소에 넣지 않음) 다듬기 전·후를 OfflineAudioContext로 렌더링하고, 소리마다 다음을 표로 남깁니다.
   - 가장 시끄러운 50ms RMS(dB) — 전/후 차이 ±1.5dB 이내
   - 피크 ÷ RMS(크레스트, dB) — 줄어들어야 함
   - 4kHz 이상 에너지 비율 — 줄어들어야 함(물·유리처럼 원래 밝은 소리는 조금만)
   - 어택 시간(0에서 최대 음량의 90%까지) — 4ms 이상
3. 연타 확인: 렌치 1타를 0.15초 간격으로 8번, 도장을 0.35초 간격으로 6번, 박자 압착을 0.54초 간격으로 8번 이어 재생해서 기계적인 반복감이 줄었는지 확인합니다.
